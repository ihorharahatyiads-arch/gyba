# Finflow

Персональный PWA-трекер на русском языке. Статический frontend без сборки и внешних библиотек, Supabase Auth + PostgreSQL. Размещение — Vercel. Домен покупать не нужно.

## Текущее состояние

Облачный проект Supabase finflow подключён. Пять таблиц созданы; RLS и проведение регулярного платежа проверены в транзакции с откатом тестовых данных. Мобильная и десктопная версии проверены в Chrome. Vercel ещё не опубликован. Демо использует вымышленные данные в памяти; не используйте его для хранения реальных данных.

## Подключение Supabase

1. Авторизуйте подключение Supabase в Codex. Создайте отдельный проект на подходящем вам тарифе и сохраните пароль БД в менеджере паролей.
2. Выполните `schema.sql` в SQL Editor нового проекта. Скрипт запускается один раз.
3. В `config.js` укажите Project URL и **publishable/anon key** из настроек проекта. Это публичные параметры. Никогда не помещайте service_role key, секретный ключ или пароль БД в приложение.
4. В Authentication задайте Site URL и разрешённые Redirect URLs на реальный адрес Vercel. Включите подтверждение email и настройте доставку писем. Для личного использования после регистрации своего пользователя отключите новые регистрации.
5. Войдите, создайте счета и категории. Пустая база не заполняется демонстрационными операциями.

## Vercel

Авторизуйте Vercel в Codex. Этот каталог готов к публикации из GitHub: Framework Preset **Other**, Build Command **node build.js**, Output Directory **dist**. Сборка копирует только публичные файлы; схема БД, тесты и инструкции в сайт не попадают. Деплой возможен через Vercel CLI из этой папки (`vercel`, затем `vercel --prod`) без GitHub либо через импорт GitHub-репозитория. CLI сначала требует `vercel login`. Не включайте чужие файлы из родительского каталога.

После получения фактического адреса `*.vercel.app` обновите Supabase Site URL/Redirect URLs. Проверьте HTTPS, регистрацию, подтверждение email, вход, восстановление пароля и сохранение после перезагрузки на двух устройствах. Только после успешного ответа Vercel считайте публикацию выполненной.

## Локальная проверка

Node.js 20+: `node server.js`, откройте http://127.0.0.1:4173. Проверки расчётов: `node --test tests/*.test.js`. Для PWA используйте HTTPS либо localhost. На iPhone: «Поделиться → На экран Домой». На Android/desktop: меню браузера → установка приложения (доступность зависит от браузера).

## Поведение и ограничения

- Суммы хранятся целыми копейками/центами. Аналитика по календарному месяцу, валюты без конвертации.
- Полная выгрузка JSON всех таблиц и CSV всех операций; импорт и восстановление из файла пока не реализованы.
- Счета и категории, на которые ссылаются операции/бюджеты/платежи, удалить нельзя: сначала удалите зависимые записи. Редактирование записей и переводы между счетами пока не реализованы.
- Регулярные правила — месячные, квартальные или годовые. Операция создаётся пользователем по кнопке «Провести», после наступления даты. Нет фонового автоматического списания. В базе операция и перенос даты атомарны.
- PWA кэширует оболочку, но не финансовые ответы API. Без сети ввод не сохраняется; офлайн-очереди нет. Сессия живёт в текущей вкладке, обновляется refresh token; при закрытии вкладки нужен новый вход.
- RLS на всех таблицах и составные внешние ключи блокируют доступ и ссылки на чужие данные. Ни серверного секретного ключа, ни паролей пользователей в исходниках нет.
- Экспортируйте JSON регулярно. Политика автоматических резервных копий зависит от выбранного тарифа Supabase; она здесь не включена и не проверена.
- Перед использованием в облаке нужно проверить изоляцию двумя тестовыми пользователями: пользователь B не должен читать/изменять записи A и создавать операции со счётом A. Проверка RLS выполнена: чтение/изменение чужого счёта, подмена владельца и ссылка на чужой счёт блокируются. Сценарий — verify-database.sql; тестовые данные откатываются.

Основные официальные справочники: https://supabase.com/docs/guides/database/postgres/row-level-security и https://vercel.com/docs/cli/deploy.
